# 应用与运行目标配置

## 应用设置

在 `src/config.py` 中至少检查：

- `gui_title`：应用窗口名称。
- `gui_icon`：GUI 图标路径。
- `supported_resolution`：支持的画面比例和最低分辨率。
- `links`：项目主页、反馈渠道和社区链接。
- `onetime_tasks`、`trigger_tasks`：任务注册列表。

## 游戏与 UU 自动启动

在应用设置中打开“游戏与 UU 自动启动”。默认启用：手动或计划启动任务时打开 UU，
通过截图 OCR 找到“战舰世界国际服”的加速按钮，确认加速成功后启动战舰世界。
Steam 安装会通过 Steam 启动，避免游戏更新后旧版本 exe 路径失效。
已运行的游戏不会重复启动。游戏准备就绪后执行所选任务；仅打开本应用不会启动 UU 或游戏。

- **UU 路径**：可留空自动检测，也可选择安装目录中的 `uu_launcher.exe`。
- **游戏路径**：可留空使用应用已记录的游戏路径，也可选择游戏 exe 或快捷方式。
- **UU 游戏名称**：必须与 UU 中的名称一致，默认“战舰世界国际服”。先在 UU 中将它添加到首页或“我的游戏”。
- **启动超时**：默认 120 秒，分别用于等待加速成功和游戏进程启动。
- **退出时关闭游戏和 UU**：默认开启。本应用真正退出时先关闭游戏，再关闭 UU，包含启动前已运行的实例。
  关闭窗口只缩到托盘时不会触发；停止战斗任务也不会触发。可在设置中关闭此选项。

自动战斗任务开始识别游戏画面后，另有固定 **5 分钟**的启动等待，用于经过 Logo、黑屏、登录和奖励页面到达港口；这些阶段共用总额度。未知画面只等待加载，不发送 Esc。超过 300 秒仍未进入主界面会记录超时并停止任务。

UU 通常以管理员权限运行，因此源码调试时也需要以管理员身份启动本应用。
权限不足会提示错误，不会把点击当成加速成功。UU 登录、选区或会员弹窗需要手动处理。
识别失败或超时会停止本次启动，处理问题后可点击应用的“启动”重试。
最近一次 UU 截图及 OCR 文字保存在 `logs/auto_launch/uu_latest.png` 和 `uu_latest.json`。
UU 的识别区域和匹配文字位于 `assets/uu/coco_annotations.json`，采用与游戏资源相同的
COCO 截图/区域格式。先识别名称栏，再识别目标卡片；坐标按 UU 窗口大小缩放。
确认游戏名称后，点击 `click_region` 指定的名称上方图标框中心；不点击 OCR 文字框。
调整区域或文字后重启应用即可生效，具体字段见 `assets/uu/README.md`。
正常关闭失败的进程会尝试终止；无法终止时记录 PID 和权限错误。
任务管理器强制结束本应用、断电等情况不能保证执行退出清理。

基础设置中的“应用启动时自动启动游戏”会在初始化时关闭，避免旧设置绕过按任务启动的行为。

## 定时启动任务

以管理员身份重启应用后，侧边栏会出现“计划任务”。点击“创建任务”，选择“自动 PVE 战斗”，设置开始时间和执行频率（一次、每天、每周、每月或自定义间隔），然后保存。战斗模式、舰船和场数使用该任务已保存的配置。

计划由 Windows 任务计划程序执行，到点启动 ok-wows 并自动执行所选任务，依次完成 UU 加速、启动游戏和战斗。可在计划页面修改、停用或删除，也可设置完成后退出。

创建计划后请在执行时间前退出当前 ok-wows，避免框架的单实例处理干扰正在执行的任务。电脑需要开机、用户保持登录且桌面解锁，才能进行前台识别与点击；关机时不会自动开机补跑。应用目录和 Python 环境移动后需要重新创建计划。

## 运行目标

`windows`、`adb`、`browser` 必须至少配置一种，也可以同时配置多种。

### Windows 原生游戏

配置 `windows` 中的：

- `exe`：游戏进程文件名列表。
- `hwnd_class`：可选的窗口类名，用于提高窗口匹配准确度。
- `interaction`：允许使用的输入方式及优先级。
- `capture_method`：允许使用的截图方式及优先级。
- HDR 和后台截图相关选项。

### Android 模拟器或设备

在 `adb.packages` 中填写游戏包名。MuMu 模拟器可使用原生截图和输入；其他模拟器或设备通常通过 ADB 工作。

### 浏览器游戏

取消 `browser` 示例配置的注释，并设置：

```python
'browser': {
    'url': 'https://example.com/game',
    'nick': 'Browser',
    'resolution': (1280, 720),
},
```

浏览器目标还需要 `playwright`。将它加入 `pyproject.toml` 中需要浏览器目标的
profile，然后重新编译对应的 `requirements.txt` 或 `requirements-web.txt`，
确保本地环境和 GitHub 打包环境都会安装该依赖。

## 替换图标

用自己的资源替换 `icons/icon.png` 和 `icons/icon.ico`。保持文件名不变可以避免额外配置；如需改名，同步修改 `src/config.py` 和 `pyappify.yml` 中的路径。

## 更新仓库

修改 `pyappify.yml` 中应用名称、profile 名称和 `git_url`：

- 正式发布建议使用独立的轻量更新仓库。
- 前期测试可以直接使用源码仓库。
- 使用独立更新仓库时，同步修改 `.github/workflows/build.yml` 中的同步目标和 Secrets。

初始化后，搜索并替换模板遗留的 `ok-script-app`、`ok-oldking`、仓库 URL、安装包名称和社区链接。
